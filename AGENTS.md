# Repository instructions

Read [`AGENT-WORKING-AGREEMENTS.md`](AGENT-WORKING-AGREEMENTS.md) before
working in this repository. This file adds only what is specific to this
repository; it never overrides Parts A–B, and a rule here that contradicts one
there is the rule that is wrong.

## Commit subjects

Commit subjects you write use `type(scope): description`. Append `(#issue)`
when the change has an issue; otherwise, omit the suffix rather than inventing
one. Subjects generated by Git or GitHub are left as generated.

This convention is local to `brandonperfetti/agent-working-agreements`. Do not
apply it to another repository unless that repository records the same rule in
its own instructions.

## CI gate

Green is these three commands, run in this order from the repository root, each
exiting 0:

```bash
./scripts/check-index.sh
./scripts/check-index.test.sh
npx --yes markdownlint-cli2
```

No environment export is needed. They are the steps of the job `check` in
`.github/workflows/check.yml`, and `check` is the required status check on
`master`. `markdownlint-cli2` lints the files its config's `globs` name
(`.markdownlint-cli2.jsonc`), symlinks included. CI runs it through
`DavidAnson/markdownlint-cli2-action`, which carries its own copy, so a local
`npx` may resolve to a different version from CI's.
